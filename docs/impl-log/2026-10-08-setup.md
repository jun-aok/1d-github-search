## スパイクの結果

| 項目 | 結果 |
| --- | --- |
| `pushState` / `replaceState` / back / forward を `useSearchParams` が検知するか | 検知する（E2E で確認。公式ドキュメント「Native History API」にも明記） |

| `exactOptionalPropertyTypes` と zod `.optional()` | `?: T \| undefined` と推論される。`z.infer` を型にすれば問題なし。手書きの `?: T` には代入できない |

| Client Component での動的ルートの `params` | `use(params)` と `useParams()` の両方で取れる |

| Route Handler の余計な export | Next.js 16.4 ではビルドが通る（型エラーにならない）。`handlers.ts` に分ける理由は「テストから import するため」に修正 |

## 迷った点・判断

- `app-prod` 1 つで prod と e2e を兼ねる設計だったが、ビルド時の env 検証でトークンが要るため、`app-e2e`（fake でビルド）を分けた。Dockerfile は同じ
- `docker compose --profile e2e up` は profile 無しの `app` も起動してしまうので、サービス名 `e2e` を明示する形にした
- `app` コンテナ内で `next build` すると `NODE_ENV=development` のため React の dev / prod が混ざって失敗する。production ビルドは Dockerfile のみとした
- create-next-app の既定にある `cacheComponents: true` は外した（サーバーでデータを取得しない方針のため不要）。Google Fonts の読み込みも外した（Docker ビルドで外部に出ない）
- Prettier の対象から Markdown と `.claude/` を外した（文書とエージェント定義を整形しない）
- Playwright のイメージは `@playwright/test` と同じ 1.59.0 に固定
