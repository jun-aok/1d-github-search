# E2E テストケース一覧

「これが全部通れば完成」と言えるかをレビューするための一覧。**この文書が正**で、`e2e/*.spec.ts` はこれを 1 対 1 で実行可能にしたもの（テスト名はこの文の言い換え）。
確認用のデータは偽の GitHub（`FakeGitHubClient`）が返す。`react` で検索すると 20 件 × 50 ページ、`__few__` で 2 件、`__empty__` で 0 件、`__rate_limited__` / `__error__` でエラー。

## 1. 検索ページ

### 1.1 初期画面と入力

- [ ] 初めて開くと、案内文が表示され、入力欄は空で、検索ボタンは押せない
- [ ] 文字を入力すると検索ボタンが押せるようになり、全部消すとまた押せなくなる
- [ ] 空白だけ（半角、全角、タブ混じり）を入力しても検索ボタンは押せず、Enter を押しても検索されない
- [ ] 入力欄には 256 文字までしか入力できない
- [ ] 256 文字ちょうどのキーワードで検索できる

### 1.2 検索の実行

- [ ] 検索ボタンを押すと、一覧と件数が表示される
- [ ] Enter キーでも検索できる
- [ ] 検索すると URL が `/?q=キーワード` になる
- [ ] 読み込み中は検索ボタンが押せず、Enter を押しても二重に検索されない
- [ ] 同じキーワードでもう一度検索ボタンを押すと、そのたびに取得し直す

### 1.3 一覧の表示

- [ ] 20 件が一覧（`<ul>` / `<li>`）として表示される
- [ ] 各行に、オーナーのアイコン、`owner/name`、description、言語、Star 数が表示される
- [ ] 行全体がリンクで、クリックすると `/repos/{owner}/{name}` へ移動する（文字の無い余白をクリックしても移動する）
- [ ] description が長くても 1 行に省略され、行の高さが揃う
- [ ] 1 ページ目は「7,297,834 件中 1〜20 件を表示」、2 ページ目は「21〜40 件」、最終の 50 ページ目は「981〜1000 件」と表示される
- [ ] 結果が 2 件なら「2 件中 1〜2 件を表示」「1 / 1 ページ」と表示される
- [ ] 結果が 1,000 件を超える（`react`）と、件数の下に「GitHub の検索 API の制限により、表示できるのは先頭の 1,000 件（50 ページ）までです。」と表示される。1 ページ目でも最終の 50 ページ目でも表示される
- [ ] 結果が 1,000 件以下（`__few__`、2 件）なら、その注意書きは表示されない

### 1.4 ページネーション

- [ ] 1 ページ目では「前へ」が押せず、「次へ」が押せて、「1 / 50 ページ」と表示される
- [ ] 「次へ」「前へ」でページが移動し、そのたびに URL の `page` が変わる
- [ ] 最後の 50 ページ目では「次へ」が押せない
- [ ] ページを移動すると、ページの先頭までスクロールする
- [ ] ページ移動中は前のページの結果が残ったまま（薄く）待ち、スケルトンには戻らない
- [ ] 検索し直すと（別のキーワードでも同じキーワードでも）1 ページ目に戻る

### 1.5 URL による復元

- [ ] `/?q=react` に直接アクセスすると、入力欄にキーワードが入り、結果が表示される
- [ ] `/?q=react&page=2` に直接アクセスすると、2 ページ目が表示される
- [ ] リロードしても同じキーワードとページの結果が表示される
- [ ] 日本語や記号を含むキーワードも URL に載り、復元できる
- [ ] 上限の 50 ページ目に直接アクセスできる

### 1.6 不正な URL

次の URL で開くと、検索せず初期画面が表示され、アドレスバーは `/` に書き換わる。

- [ ] `page` が数字でない（`page=abc`）
- [ ] `page` が 0、負の数、51（上限超え）
- [ ] `page` が `02`（先頭 0）や `2.0`（小数表記）
- [ ] `page` が空（`page=`）
- [ ] `q` が空、または空白だけ
- [ ] `q` が無く `page` だけある
- [ ] `q` が 257 文字

### 1.7 総ページ数を超えるページ

- [ ] `/?q=__few__&page=3`（結果は 2 件 = 1 ページ）を開くと、「このページには結果がありません」、件数「2 件」、「3 / 1 ページ」が表示され、一覧は出ない
- [ ] そこで「前へ」を押すと、1 つ前ではなく最終ページ（1 ページ目）へ移動する

### 1.8 読み込み中・0 件・エラー

- [ ] 最初の検索中（前の結果が無い）は、スケルトンが表示される
- [ ] 前の結果があるときの再検索中は、前の結果が表示されたまま待つ
- [ ] 0 件のときは「一致するリポジトリは見つかりませんでした」と表示され、一覧とページネーションは出ない
- [ ] レート制限のときは、上限に達した旨、再試行ボタン、問い合わせ番号が表示される
- [ ] 通信エラーのときは、失敗した旨、再試行ボタン、問い合わせ番号が表示される
- [ ] ネットワーク断（BFF に届かない）のときは、エラーと再試行ボタンが表示され、問い合わせ番号は表示されない
- [ ] BFF が想定外の 500 を返しても、応答が JSON でなくても、白画面にならずエラーと再試行ボタンが表示される
- [ ] 再試行ボタンを押すと、もう一度取得する（通信エラーでもレート制限でも）
- [ ] 一時的な失敗は、再試行で結果の表示に回復する
- [ ] エラー表示のあとに別のキーワードで検索すると、結果の表示に戻る
- [ ] 失敗した検索は覚えておかず、同じ条件をもう一度表示するときは必ず取得し直す（★設計のみ）

## 2. 詳細ページ

- [ ] `/repos/react/react` に直接アクセスすると、`owner/name`、アイコン、言語、description が表示される
- [ ] Star 数、Watcher 数、Fork 数、Issue 数がカンマ区切りで（丸めずに）表示される。Watcher 数は `subscribers_count` の値
- [ ] 「GitHub で開く」リンクは、リポジトリの GitHub ページを別タブで開く
- [ ] 言語が無いリポジトリでは「—」と表示される
- [ ] 読み込み中はスケルトンが表示され、取得できたら詳細に替わる
- [ ] 存在しないリポジトリでは「見つかりません」の案内と、検索ページへ戻るリンクが表示される
- [ ] レート制限のときは、上限に達した旨、再試行ボタン、問い合わせ番号が表示される
- [ ] 通信エラーのときは、失敗した旨、再試行ボタン、問い合わせ番号が表示される
- [ ] 再試行ボタンを押すともう一度取得し、一時的な失敗なら詳細の表示に回復する
- [ ] ヘッダーのタイトルをクリックすると検索ページ（初期画面）へ戻る

## 3. 画面の行き来

- [ ] 一覧の行から詳細へ移り、ブラウザバックすると、検索キーワードとページが残っている
- [ ] 一覧 → 詳細 → 戻る、のとき一覧を取得し直さない（★設計のみ）
- [ ] 詳細から戻った先で、別の行を開き直せる
- [ ] 別のキーワードで検索したあとブラウザバックすると、前のキーワードの結果に戻り、入力欄の内容も URL に合う。フォワードで進める
- [ ] ページ送りのあとブラウザバックすると、前のページに戻る
- [ ] 初期画面から検索したあとブラウザバックすると、初期画面に戻る

## 4. 共通

- [ ] ヘッダーにタイトルがあり、検索ページ（`/`）へのリンクになっている。結果表示中でもエラー表示中でも使える
- [ ] `GET /api/health` が 200 と `{ status: "ok" }` を返す
- [ ] 応答に最低限のセキュリティヘッダー（`X-Content-Type-Options` など 3 つ）が付く

## 5. 画面幅

- [ ] 検索の 7 状態（初期 / 結果 1 ページ目 / 最終ページ / 範囲外 / 0 件 / レート制限 / 通信エラー）と詳細の 4 状態（表示 / 404 / レート制限 / 通信エラー）で、画面幅 320px・768px・1280px のどれでも横スクロールが出ない
- [ ] モバイル端末（Pixel 7）でも、上の 11 画面で横スクロールが出ない
- [ ] 1280px では一覧の行に言語と Star 数が見え、モバイル端末では見えない（`owner/name` と description は見える）
- [ ] モバイル端末のタッチ操作で、検索、ページ移動、詳細への遷移ができる

## 6. BFF の応答の形（★設計のみ）

- [ ] 検索・詳細のエラーは、障害なら 502 `UPSTREAM_ERROR`、レート制限なら 429 `RATE_LIMITED`、404 なら `NOT_FOUND`、入力不正なら 400 `BAD_REQUEST` を返す
- [ ] エラー応答の `requestId` は、ヘッダー `x-request-id` と本文で一致する
- [ ] production では応答に `detail`（詳細）を含まない
- [ ] 検索の成功時は `{ totalCount, items }` を返す

## 7. モックとの一致（DOM 比較）

検索 9 状態（初期 / 読み込み中 / 結果 / 再取得中 / 0 件 / 少数 / 範囲外 / レート制限 / 通信エラー）と詳細 6 状態（読み込み中 / 表示 / 言語なし / 404 / レート制限 / 通信エラー）のそれぞれで:

- [ ] A. 構造: 要素の役割・名前・文言・無効状態・リンク先が、モック（`mock/*.html?state=…`）と一致する
- [ ] B. 見た目: クラス名を含む `<header>` と `<main>` の DOM が、モックと一致する（問い合わせ番号などの可変値と、モックのスクリプト用の属性は除く）

## レビュー用の注記

- **★設計のみ**: 要件（`requirements.md`）に明記が無く、設計（`design.md`）にだけある振る舞い。レビューの結果、残すことに決定
- **E2E でテストしていないもの**（単体テストで扱う）: production でトークン未設定ならビルドが止まる、development でのエラー詳細の表示、ログの出力先と内容、描画時の例外で `error.tsx` が出る
- 「前へ」で 1 ページ目に戻ったときの URL は `page` を省略する（`/?q=react`）に決定
- レート制限時の「約 N 秒後に再試行できます」は設計から外した（モックどおりの固定文言）
- 1,000 件超の注意書き（1.3 の 2 件）を追加。モックの「結果」「再取得中」の状態にも注意書きが入り、7 節の DOM 比較で一致を確かめる。1,000 件ちょうど・1,001 件の境界は単体テスト（`exceedsMaxResults`）で扱う
- 合計 168 件（desktop 155 + mobile 13）。すべて Green。ループ前は 166 件（desktop 153 + mobile 13）で、1,000 件超の注意書きの 2 件を完成後に足した
