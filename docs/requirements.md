# 要件

GitHub のリポジトリを検索する Web アプリケーション。判定できることだけを書く。
要望は `docs/request.md`、判断と設計は `docs/design.md`、画面は `mock/`。

## 制約

- Next.js v16 以降、App Router
- TypeScript（`strict`）
- テストコードを含める。単体・コンポーネントテストに加えて E2E（Playwright）を含める
- Docker Compose だけで動かせる。development（`docker compose up`）と production（production ビルドのイメージ。`docker compose --profile prod up app-prod`）の 2 つの起動方法があり、README に手順がある
- production イメージは `GET /api/health` で死活確認できる
- CI（GitHub Actions）で lint / 型チェック / 単体テスト / E2E / ビルドを実行し、すべて通る
- README に、工夫した点・こだわった点、選択理由、AI の利用方法を書く

## 共通

- レスポンシブ対応: 画面幅 320px〜1280px で横スクロールなしに表示・操作できる。モバイル幅では 1 カラム
- ヘッダーのタイトルは検索ページへのリンク
- 環境: production と development を分ける
  - production で `GITHUB_TOKEN` が未設定なら、デプロイ（ビルド・起動）がエラーで止まる（`GITHUB_CLIENT=fake` のテスト用構成は除く）。development では未設定でも動く
- エラー処理:
  - 想定外のエラーでも白画面にならず、エラー画面と再試行の手段が表示される
  - BFF が返すエラー応答には `requestId` が含まれ、エラー画面に問い合わせ番号として表示され、ログと突き合わせられる。BFF に届かなかったエラー（ネットワーク断）には番号が無く、表示もしない
  - production: エラーをログに出力する。画面と API の応答にはエラーの詳細（スタックトレース、GitHub の生のメッセージ）を出さない
  - development: エラーの詳細を画面に表示する
  - ログの記録先は差し替え可能で、既定は標準出力に JSON 1 行

## 検索ページ `/`

- キーワードを入力し、GitHub API `search/repositories` の結果を一覧表示する
- 検索の実行はボタンまたは Enter。空文字・空白のみ、または読み込み中は実行できない（ボタン無効）。最大 256 文字。同じキーワードでも、実行するたびに最新の結果を取得する
- キーワードとページは URL クエリに持つ（`/?q=react&page=2`）。リロード・共有・ブラウザバックで同じ結果になる
- URL のパラメータが不正なとき（`page` が 1〜50 の整数でない、`q` が空・空白のみ・256 文字超、`q` が無いのに `page` がある）は、検索せず初期画面を表示する。URL も `/` に書き換える
- 総ページ数を超えるページを指定されたときは、空のページを表示する（「このページには結果がありません」、件数は「N 件」のみ、ページネーションは「現在 / 総ページ数」で「前へ」は最終ページへ）
- 1 行: オーナーアイコン / `owner/name` / description（1 行省略）/ 言語 / Star 数（言語と Star 数はモバイル幅では非表示）。行全体がリンクで、詳細ページへ遷移する
- 件数表示「N 件中 a〜b 件を表示」。a = `(page - 1) × 20 + 1`、b = `(page - 1) × 20 + そのページの件数`
- 結果が 1,000 件を超えるとき（N ≥ 1,001）は、件数表示の下に注意書き「GitHub の検索 API の制限により、表示できるのは先頭の 1,000 件（50 ページ）までです。」を表示する。どのページでも表示する。1,000 件以下では表示しない
- ページネーション: 1 ページ 20 件。「前へ」「次へ」と「現在 / 総ページ数」。総ページ数は `ceil(min(N, 1000) / 20)`。検索し直すと 1 ページ目に戻る。ページを移動したら先頭へスクロールする
- 状態: 初期（案内文）/ 読み込み中（前の結果があれば薄く表示したまま待つ。無ければスケルトン）/ 0 件 / レート制限（再試行ボタン）/ 通信エラー（再試行ボタン）

## 詳細ページ `/repos/{owner}/{repo}`

- モーダルではなくページ。直接アクセスでも表示できる
- 表示: オーナーアイコン / `owner/name` / 言語 / description / Star 数 / Watcher 数 / Fork 数 / Issue 数 / GitHub へのリンク（別タブ）
- 数値はカンマ区切りで丸めない。言語が `null` なら「—」
- Watcher 数は `GET /repos/{owner}/{repo}` の `subscribers_count`。Issue 数は `open_issues_count`
- ヘッダーのタイトルで検索ページへ戻る。ブラウザバックでは検索状態が残る（入力欄の内容も URL のキーワードに合う）
- 状態: 読み込み中（スケルトン）/ 404（検索ページへのリンク）/ レート制限（再試行ボタン）/ 通信エラー（再試行ボタン）

## スコープ外

以下は実装しない。

- 絞り込み・並び替えの UI、検索修飾子（`language:go` 等）の動作保証
- 無限スクロール、1,000 件を超える結果（表示はしない。超えていることは注意書きで知らせる）
- 検索履歴、お気に入り、サジェスト
- 詳細ページの追加情報（README、トピック、ライセンス、コミット等）、オーナーページ
- ログイン、利用者ごとのトークン、非公開リポジトリ
- 多言語対応、ダークモード、オフライン対応
- 旧ブラウザ・320px 未満の対応保証、WCAG 準拠の監査
- 性能目標の数値化、監視・ログ基盤（記録先の抽象化と標準出力への出力まで）、サーバー側キャッシュ基盤、スケーリング設計
- ブラウザ側のエラーをサーバーへ送信する仕組み
