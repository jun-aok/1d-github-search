# E2E テスト（Playwright）

`docs/workflow.md`「ループの前」3 番で書いた E2E。**これが全部通れば完成**と言えるかを、レビューするための一覧。
アプリ本体が無い段階で書いたので、書いた時点では `GET /api/health` などを除いてすべて Red（失敗）が正しい。現在はすべて Green。

- 対象: `app-e2e`（production ビルド + `GITHUB_CLIENT=fake`）。GitHub は `FakeGitHubClient`（`src/mocks/fixtures/*.json`）
- 実行: `docker compose --profile e2e up --build --abort-on-container-exit --exit-code-from e2e e2e`（終わったら `docker compose --profile e2e down`）
- プロジェクト: `desktop`（Desktop Chrome。`*.mobile.spec.ts` 以外すべて）と `mobile`（Pixel 7。`*.mobile.spec.ts` だけ）。`playwright.config.ts` で分けている
- 合計 168 件（desktop 155 + mobile 13）。1 件ごとに独立（実行順や他のテストの状態に依存しない）。`skip` / `only` / `fixme` は使っていない

## 使うキーワード（FakeGitHubClient）

| 画面 | URL | 応答 |
| --- | --- | --- |
| 検索 | `?q=react`（それ以外のキーワードも同じ） | 20 件、`total_count` 7,297,834（総ページ数 50）。どのページでも同じ 20 件 |
| 検索 | `?q=__few__` | 2 件（1 ページ） |
| 検索 | `?q=__empty__` | 0 件 |
| 検索 | `?q=__rate_limited__` / `?q=__error__` | レート制限 / 障害 |
| 詳細 | `/repos/react/react`（owner が下記以外） | `repo-react-react.json` |
| 詳細 | `/repos/__not_found__/x` / `__rate_limited__/x` / `__error__/x` | 404 / レート制限 / 障害 |

## 方針

- 要素は role / label / text で特定する（文言は `mock/` が正）。**`data-testid` は 1 つも使っていない**
  - 例外として、アイコン（`alt=""` の装飾画像は role を持たない）だけ `row.locator("img")` で特定している
  - Next.js のルートアナウンサーも `role="alert"` なので、エラー表示は文言で絞っている（`alertWith`）
- 時間では待たない（`waitForTimeout` なし）。自動で待つアサーション、`expect.poll`、通信の保留（`holdRequests`）を使う
- ブラウザ → BFF の通信は `page.route` で保留・失敗・差し替えができる（読み込み中、ネットワーク断、一時的な失敗からの回復の再現）。BFF → GitHub は `FakeGitHubClient`
- オーナーアイコンの GitHub への通信は、1x1 の画像に差し替えて止めている（`support/test.ts`。全テストで自動）
- 期待値のデータは `src/mocks/fixtures/*.json` から読む（アプリと同じ出どころ）

## モックとの DOM 比較（`dom-compare-*.spec.ts`）

`<header>` と `<main>` を、モック（`file:///app/mock/*.html?state=...`。Tailwind はブラウザ版を CDN から読む）と実装で比べる。対応表は `support/mock-states.ts`。

| 比較 | 比べるもの | 正規化 |
| --- | --- | --- |
| A. 構造 | `ariaSnapshot()` の文字列（役割・名前・文言・`disabled`・リンク先・入力欄の値） | 問い合わせ番号（UUID）を `<REQUEST_ID>` に |
| B. 見た目 | クラス名を含む DOM | 属性とクラス名を並べ替え / 空白を詰める / `display: none` の要素を除く / 入力欄は `value` 属性でなく現在の値 / UUID を伏せる / モックのスクリプト用の属性（`id` `for` `data-view` `data-request-id` `onsubmit`）と空の `class` は比べない |

モック上部の状態切り替えバーは `<header>` / `<main>` の外なので比較に入らない。

## 要件のうち、テストにしていない・判断が要るもの

- 「production で `GITHUB_TOKEN` 未設定ならビルド・起動が止まる」「development / production の `detail` の出し分け」「ログの記録先」「エラーのログ出力」: E2E の対象環境（production + fake）では確かめられない。`env.ts` / `respond.ts` / `withErrorHandling` の単体テストで扱う
- 「描画時の想定外の例外でエラー画面（`error.tsx`）」: 外から例外を起こす手段が無い。BFF の 500 や JSON でない応答でも白画面にならないことだけを確かめている
- 「存在しない URL → `not-found.tsx`」: 要件にないので書いていない
- 「description 1 行省略」: 見た目の調整だが、「行の高さが揃う」ことで間接的に確かめている
- 「モバイル幅では 1 カラム」: 検索・詳細とも元々 1 カラムのため、横スクロールが無いことの確認に含めた
- 「検索ボタンの無効 = 読み込み中」: 最初の検索中とページ移動中、再検索中で確かめている
- 1 ページ目の URL は `page` を省略する（`/?q=react`）と決定。テストもそれで比べている
- design 5 節にだけある振る舞い（要件に明記なし）を 3 件含む: 失敗は覚えず取り直す（`search-states`）、一覧 → 詳細 → 戻るで再取得しない（`navigation`）、BFF のエラー応答の形（`bff-errors`）。レビューの結果、残すことに決定
- レート制限の文言はモックどおり固定。「約 N 秒後に再試行できます」は設計から外した（`retryAfter` は応答に含めるが画面には出さない）
